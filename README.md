# ReAct-агент підтримки гравців мобільної гри

ДЗ1, курс «Autonomous Agent Design» (GoIT Neoversity). Автор — Михайло Кухарук.

## 1. Опис проєкту

ReAct-агент на LangGraph, який відповідає на звернення гравців мобільної гри «Forge & Craft»:
перевіряє профіль гравця, покупки, версію клієнта, стан серверів, шукає відомі проблеми й рахує
компенсацію. Цикл LLM → tools → LLM має захисні механізми (ліміт кроків, тайм-аут, детекцію
зациклення), кожен крок пишеться в `trajectory.json`, а фінальна відповідь — структурований об'єкт
`SupportAnswer`.

## 2. Доменна задача

Служба підтримки отримує типові звернення: «оплатив, а кристали не прийшли», «гра вилітає»,
«чи працюють сервери», «чи буде компенсація». Відповідь вимагає кількох кроків і різних джерел
даних, а наступний крок залежить від результату попереднього — тому обрано ReAct-агента, а не
фіксований ланцюг. Дані інструментів тестові (`mock_data.py`), щоб результати були відтворюваними.

Інструменти:

| Інструмент | Що робить | Валідація входу |
|---|---|---|
| `get_player_profile` | рівень, платформа, версія, бан | `P-1234`, нормалізація `p1001 → P-1001` |
| `get_purchase_status` | статус оплати й видачі товару | `P-1234` + `T-1234`; транзакція іншого гравця → `forbidden` |
| `check_client` | чи підтримується версія, відомі краші | платформа `android`/`ios`, версія `X.Y.Z`; «latest» відхиляється |
| `search_known_issues` | пошук у базі відомих проблем | запит 3–200 символів, `limit` 1–5 |
| `get_server_status` | стан серверів регіону | `eu`/`na`/`asia`/`latam`, нормалізація «Європа → eu» |
| `calculate_compensation` | розрахунок компенсації (без нарахування) | тип проблеми з переліку, рівень 1–200; для `server_outage` потрібні години |

## 3. Архітектура

```
START → agent ──(є tool_calls і ліміти не вичерпано)──► tools ──► agent …
            └──(фінальна відповідь / ліміт / тайм-аут / зациклення)──► finalize → END
```

- **agent** — Claude Sonnet 5.5 (`claude-sonnet-5-5`) з прив'язаними інструментами; системний промпт
  описує мету, політики й критерій завершення.
- **tools** — безпечне виконання: перевірка, що інструмент існує; валідація аргументів Pydantic
  (помилка повертається моделі текстом, граф не падає); виконання з урахуванням залишку часу.
- **finalize** — якщо агент завершив сам, окремий виклик моделі в нативному режимі structured
  output повертає `SupportAnswer`; якщо спрацював ліміт — запасна відповідь із причиною зупинки
  й ескалацією.
- **Захисні механізми** (`safety.py`): `max_steps = 10` викликів моделі, загальний `timeout = 120 с`,
  зациклення — 3 однакові виклики інструмента поспіль (та сама назва й ті самі аргументи).

Схема відповіді `SupportAnswer`: `answer`, `category` (purchase / technical / account / server / other),
`resolved`, `next_action` (none / compensation / escalate / wait), `evidence` (факти з інструментів із
назвою інструмента), `compensation` (кристали або `null`).

Особливості моделі: моделі Claude 5.5 не приймають `temperature`/`top_p` і примусовий виклик
інструмента, тому structured output зроблено через `method="json_schema"`, а тести перевіряють
стабільні поля (інструменти, категорію, наступну дію, суму компенсації), а не дослівний текст.

## 4. Інструкція запуску

**Google Colab** (основний спосіб):

1. Відкрити `hw1_colab.ipynb` у Colab.
2. Додати в Colab Secrets ключ `ANTHROPIC_API_KEY` і дозволити ноутбуку доступ до нього.
3. Вказати `REPO_URL` у першій клітинці. `DRY_RUN = True` — пробний прогін одного тест-кейсу,
   `False` — повний прогін (5 тест-кейсів + 3 демо).
4. Runtime → Run all. Наприкінці ноутбук завантажує `test_results.json`, `demo_results.json`, `trajectory.json`.

**Локально:**

```bash
pip install -r requirements.txt
cp .env.example .env              # вписати ANTHROPIC_API_KEY
export $(cat .env | xargs)
python -m pytest -v               # юніт-тести інструментів, захисту й графа (без API)
python test_runner.py             # тест-кейси + демо, пише JSON-файли
```

## 7. Висновки та обмеження

_Заповнюється після прогону._

Відомі обмеження: дані тестові; пошук відомих проблем — за ключовими словами (у ДЗ2 його замінить
векторний пошук); відповіді моделі не детерміновані, тому результати прогонів можуть дещо відрізнятися.

## 8. Структура файлів

- `tools.py` — Pydantic-схеми та інструменти
- `mock_data.py` — тестові дані гравців, покупок, версій, серверів і відомих проблем
- `agent.py` — LangGraph-граф, системний промпт, схема `SupportAnswer`
- `safety.py` — `StopController`, `LoopDetector`
- `logger.py` — `TrajectoryLogger`
- `test_runner.py` — тест-кейси, демо лімітів, збір результатів
- `tests/` — юніт-тести (pytest): інструменти, захисні механізми, граф на сценарній моделі
- `hw1_colab.ipynb` — запуск у Google Colab
- `trajectory.json`, `test_results.json`, `demo_results.json` — результати (генеруються)
- `requirements.txt`, `.env.example`
